Vector Database API

Store, search, and manage high-dimensional vectors with sub-millisecond latency. Built for AI applications requiring semantic search, similarity matching, and real-time vector operations.

⚡ Edge-Optimized

All vector operations are optimized for edge computing with global distribution and automatic scaling based on demand.

Overview

The Vector Database API provides a fully managed vector database service optimized for AI and machine learning workloads. Support for up to 65,536 dimensions with automatic indexing and real-time search capabilities.

Authentication

All API requests require authentication using your API key in the Authorization header:

Authorization: Bearer sk_live_...

Collections

Collections are the top-level containers for organizing your vectors. Each collection can have its own schema, indexing strategy, and configuration.

POST /v1/collections

Create a new collection with specified configuration.

curl -X POST "https://api.shmry.com/v1/collections" \
  -H "Authorization: Bearer $SHMRY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "product_embeddings",
    "dimension": 1536,
    "metric": "cosine",
    "description": "Product catalog embeddings"
  }'

Parameters

Parameter Type Required Description
name string Yes Unique collection name (alphanumeric + underscore)
dimension integer Yes Vector dimension (1-65,536)
metric string No Distance metric: "cosine", "euclidean", "dotproduct"
description string No Human-readable description
GET /v1/collections

List all collections for your account.

curl -X GET "https://api.shmry.com/v1/collections" \
  -H "Authorization: Bearer $SHMRY_API_KEY"

Vector Operations

Insert, update, and delete vectors within collections. Each vector can include metadata for filtering and retrieval.

POST /v1/collections/{collection}/vectors

Insert or update vectors in a collection.

curl -X POST "https://api.shmry.com/v1/collections/product_embeddings/vectors" \
  -H "Authorization: Bearer $SHMRY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "vectors": [
      {
        "id": "prod_001",
        "vector": [0.1, 0.2, 0.3, ...],
        "metadata": {
          "name": "Premium T-Shirt",
          "category": "clothing",
          "price": 29.99
        }
      }
    ]
  }'
DELETE /v1/collections/{collection}/vectors

Delete vectors by ID or filter criteria.

curl -X DELETE "https://api.shmry.com/v1/collections/product_embeddings/vectors" \
  -H "Authorization: Bearer $SHMRY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "ids": ["prod_001", "prod_002"]
  }'

Vector Search

Perform similarity search using vector queries with optional metadata filtering.

POST /v1/collections/{collection}/search

Search for similar vectors.

curl -X POST "https://api.shmry.com/v1/collections/product_embeddings/search" \
  -H "Authorization: Bearer $SHMRY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "vector": [0.1, 0.2, 0.3, ...],
    "top_k": 10,
    "include_metadata": true,
    "filter": {
      "category": "clothing",
      "price": {"$lt": 50.0}
    }
  }'

Search Parameters

Parameter Type Required Description
vector array Yes Query vector (same dimension as collection)
top_k integer No Number of results (default: 10, max: 100)
include_metadata boolean No Include metadata in results (default: false)
filter object No Metadata filter criteria

Metadata & Filtering

Filter search results using metadata with support for complex queries:

// Simple equality filter
"filter": {"category": "electronics"}

// Numeric range filter
"filter": {"price": {"$gte": 10, "$lte": 100}}

// Multiple conditions
"filter": {
  "$and": [
    {"category": "clothing"},
    {"price": {"$lt": 50}},
    {"in_stock": true}
  ]
}

// Text search
"filter": {"name": {"$contains": "shirt"}}

Index Types

Shmry automatically selects the optimal indexing strategy based on your collection size and query patterns:

Index Type Best For Build Time Query Speed
Flat Small collections (< 10K vectors) Instant O(n) - Linear scan
IVF Medium collections (10K - 1M) Fast O(log n) - Approximate
HNSW Large collections (> 1M) Medium O(log n) - Approximate

Rate Limits

Rate limits are applied per API key and vary by plan:

Plan Requests/min Vectors/min Collections Max Dimension
Free 60 1,000 3 1,536
Builder 300 10,000 10 4,096
Scale 1,200 100,000 50 16,384
Enterprise Custom Custom Unlimited 65,536

Error Codes

Common HTTP status codes and their meanings:

Code Error Description
400 Bad Request Invalid parameters, dimension mismatch, or malformed request
401 Unauthorized Invalid or missing API key
404 Not Found Collection or vector not found
409 Conflict Collection name already exists or vector ID conflict
429 Rate Limited Too many requests, try again later
500 Internal Error Server error, contact support

💡 Pro Tip

Use batch operations for inserting multiple vectors to improve throughput. The optimal batch size is 100-1000 vectors per request.
